# My_shell-
Проект по bash
Краткая информация всех файлов
1) shell.h - содержит общие типы и интерфейсы всех модулей bash
---------------------------------------------------------------------------------------------------------------------------------------
2) lexer.c - лексический анализ: строка -> слова и операторы. Лексер работает слева направо, сначала отделяет метасимволы и операторы, а внутри слова собирает обычные, экранированные и заключённые в кавычки фрагменты в одну строку. Он только выдаёт токены парсеру.
---------------------------------------------------------------------------------------------------------------------------------------
3) parser.c - синтаксический анализ методом рекурсивного спуска. Парсер реализует каждый уровень грамматики отдельной функцией. Функция более высокого уровня вызывает нижележащие, а циклы собирают повторяющиеся операторы. Так приоритеты операторов задаются структурой вызовов, а результатом становится дерево, которое исполнитель позже обходит. Грамматика:
 list     = and_or { (";" | "&" | NL) [and_or] }
 and_or   = pipeline { ("&&" | "||") pipeline }
 pipeline = command { "|" command }
 command  = simple | "(" list ")" { redirection }
----------------------------------------------------------------------------------------------------------------------------------------
4) ast.c - работа с деревом команд. print_ast() показывает её для отладки, ast_to_string() восстанавливает текстовую форму для отображения задания. Сериализатор удобен для текущих деревьев парсера, но его стоит воспринимать как форматированное представление ограниченного языка, а не универсальный способ без потерь закодировать любое возможное дерево.
-----------------------------------------------------------------------------------------------------------------------------------------
5) executor.c - исполнение дерева команд. Любая внешняя команда, конвейер, подоболочка и фоновый запуск проходят через launch_job(): создаётся задание, для каждой стадии делается fork, потом задание ждут (передний план) или отпускают (фон). Встроенные команды вне конвейера выполняются в самом интерпретаторе. Потомок после fork никогда не возвращается в главный цикл: он завершается через _exit() либо заменяет образ вызовом exec.
------------------------------------------------------------------------------------------------------------------------------------------
6) builtins.c - встроенные команды: cd, pwd, echo, help, exit, jobs, fg, bg, kill, wait. Здесь разбираются аргументы и формируются сообщения об ошибках, сами операции над заданиями выполняет модуль jobs.
------------------------------------------------------------------------------------------------------------------------------------------- 
7) jobs.c - управление заданиями. Модель:
Задание — один конвейер, одна команда или одна подоболочка, в нём один или несколько процессов (Proc). При включённом управлении заданиях (интерактивный режим) все процессы задания лежат в одной группе процессов, pgid = pid первого процесса. setpgid вызывают и родитель, и потомок (порядок после fork не определён).
Задание переднего плана получает терминал (tcsetpgrp), после завершения или остановки терминал возвращается интерпретатору, а его режимы (termios) восстанавливаются. SIGCHLD обработчика нет: состояния обновляются опросом waitpid(-1, ..., WUNTRACED | WCONTINUED) — неблокирующим перед приглашением и блокирующим, пока интерпретатор ждёт задание. Так таблица меняется только из основного потока управления, и ей не нужна защита от обработчика сигнала. Единственный асинхронный обработчик — SIGINT: он пишет перевод строки (write безопасен) и прерывает read, чтобы главный цикл вывел новое приглашение. Здесь же — единственное глобальное состояние: таблица заданий и терминал.
----------------------------------------------------------------------------------------------------------------------------------------------
8) main.c - режимы запуска и главный цикл. Он определяет режим, при необходимости собирает несколько строк, вызывает лексер и парсер, затем либо печатает результат для отладки, либо передаёт AST исполнителю.
